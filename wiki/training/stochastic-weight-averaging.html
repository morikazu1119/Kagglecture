Stochastic Weight Averaging (SWA)

Stochastic Weight Averaging (SWA)は、学習後半で得た複数時点のモデルweightを等しい重みで平均し、1つの推論用モデルを作る方法です。checkpointを何個も同時推論するprediction ensembleとは違い、最終的には1組のweightだけを使えます。

Kaggleでは「終盤のcheckpointが少しずつ揺れる」「複数checkpointをensembleしたいが推論costを増やしたくない」ときの候補です。ただし、異なる解へ大きく離れたweightを無条件に平均すればよいわけではありません。

仕組み

直感は「最後の1点を選ぶ代わりに、学習後半で訪れた複数のweightを中央へ寄せる」です。以下は理解用の模式例で、Kaggleの実測値ではありません。

checkpoint A

weight = 0.42

checkpoint B

weight = 0.50

checkpoint C

weight = 0.58

SWA

(0.42 + 0.50 + 0.58) / 3 = 0.50

模式例。実際のnetworkでは全parameter tensorを要素ごとに平均します。

PyTorchのAveragedModelは、渡されたparameterのrunning equal averageを標準で計算します。典型的には通常学習の後半からweight収集を始め、必要ならSWA用learning-rate scheduleへ切り替えます。

式で見る

n個のweightを θ₁, …, θₙ とすると、SWA weightは θSWA = (1/n) Σ θᵢ です。EMAのように新しいweightほど指数的に大きな係数を与えるのではなく、収集対象を等重みで扱うのが基本です。

使い分け

方法何を平均するか推論model数向く状況
SWA複数時点のweightを等重み1学習後半の近いcheckpointをまとめたい
EMAweightを指数移動平均1学習中の更新noiseを継続的にならしたい
Checkpoint averaging / model soup選んだcheckpointのweight1保存済みcheckpointをofflineで平均したい
Prediction ensemble各modelの予測複数異なるmodelのerror diversityを残したい

SWAと「top-k checkpointの単純weight平均」は実装上近い場合がありますが、標準的SWAは学習後半のweight trajectoryを収集するtraining procedureまで含む概念です。Kaggle writeupで「SWA」「model soup」「offline weight averaging」が混在する場合は、何をいつ平均したかを確認します。

Kaggleでの実例

BirdCLEF+ 2026: ProtoSSMで +0.007 LB

19位solutionではProtoSSMにSWAを使用し、writeupのablationで0.951 → 0.958 LB、SWA開始比率start_frac=0.55、70 epochsと報告しています。定量差が明示されているためEvidence Aです（BirdCLEF 2026 — Solution Writeup (19th place)）。

Feedback Prize - Predicting Effective Arguments: 7位

7位solutionは有効だった手法としてSWAを列挙し、DeBERTa系model、soft pseudo labeling、AWPなどと併用しています。SWA単独のablation値は示されていないためEvidence Bとして扱います（7th Place Solution）。

PhysioNet ECG Image Digitization: offline weight averaging

26位solutionではvalidation loss / scoreで上位3modelを保持し、training後にoffline weight averagingを実施しています。これは厳密なSWA training loopというよりcheckpoint weight averagingの実例で、Kaggleで用語が近接して使われる例として区別しておくと安全です（26th Place Solution）。

注意点

  • BatchNorm統計: parameterを平均した後のmodelではBatchNormのrunning statisticsが合わないことがあります。PyTorchはupdate_bn()で再計算する方法を提供しています。
  • 平均開始が早すぎる: まだ大きく学習中のweightまで混ぜると、良い終盤解から離れる可能性があります。swa_startはValidationで確認します。
  • 異なるbasinの無条件平均: weight空間で離れたmodel同士の単純平均が常に機能するとは限りません。異architectureのensemble代替にはなりません。
  • LBだけで選ばない: SWA開始epochや収集範囲をPublic LBだけで調整せず、OOF / held-out Validationでsingle checkpointと比較します。
