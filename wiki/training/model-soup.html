Model Soup

Model Soupは、同じarchitecture・同じpretrained modelからfine-tuningした複数checkpointの重みを平均し、1つの推論モデルへ統合する方法です。

Prediction ensembleと違い、完成後は1モデルだけをforwardするため、候補を複数保存できる一方で本番の推論時間を増やしたくない場面に向きます。ただし、無関係な重みを何でも平均してよいわけではありません。

仕組み

候補modelのparameterを θ₁, θ₂, …, θₖ とすると、Uniform Soupは同じparameter位置を単純平均して θ_soup = (θ₁ + … + θₖ) / k を作ります。重要なのはpredictionではなくweightを平均する点です。

平均する場所が違う

Model Soupは推論前にweightを1組へまとめる。

Uniform SoupとGreedy Soup

Uniform Soupは候補をすべて等平均します。Greedy Soupはvalidation性能の高い候補から始め、1つ追加して平均したときにvalidationが改善する候補だけを採用します。原論文では、候補選択を行うGreedy Soupが、質の低い候補を混ぜるリスクを抑える方法として提案されています（Wortsman et al., 2022）。

Model Soupの原論文は、共通のpretrained modelから異なるhyperparameterでfine-tuneしたモデルが同じ低loss basinにある場合、weight averagingが有効になりやすいことを示しています。逆に、独立に学習した全く異なる解やarchitectureをそのまま平均する用途ではありません。

注意点

architectureやparameter対応が違うmodelは平均できない

weight tensorのshapeと意味が対応している必要があります。異種backboneを混ぜたい場合はprediction ensembleを使います。

候補を増やせば必ず良くなるわけではない

低品質checkpointや異なるbasinのmodelをUniform Soupへ混ぜると悪化し得ます。OOF / validationでUniformとbest singleを比較し、候補選択自体を同じvalidationへ過適合させないようにします。

BatchNormなどbufferも確認する

parameterだけでなくrunning statisticsを持つmodelでは、何を平均・再計算するかを実装ごとに確認します。

「推論costが1 model」はSoup作成後の話

候補modelのfine-tuningと保存には計算・storageが必要です。Inference budgetを節約する手法であって、training costを無料にする手法ではありません。

Quick Reference

  • 同じarchitecture・共通pretrained weightから得た複数checkpointが候補。
  • Uniform Soupは全候補を等平均、Greedy Soupはvalidationで候補を選ぶ。
  • Prediction ensembleと違い、完成後のforwardは1 model分。
  • best single / SWA / EMA / prediction ensembleと同じOOFで比較する。
  • 異種architectureや遠いweightを無条件に平均しない。
