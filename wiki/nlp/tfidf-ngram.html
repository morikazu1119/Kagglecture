TF-IDF / Word・Character N-gram

TF-IDFは、文章に出た単語や文字列を数えつつ、「どの文書にも出る語」は軽く、「その文書で特徴的な語」は重くするtext representationです。

KaggleではTransformerより古い手法ですが、語彙・定型句・綴り・suffix/prefixがtargetに直結する問題では今でも強く、CPUで高速に回せるbaseline・diversity modelとして価値があります。

理解用の模式例。Kaggle実測値ではありません。

単純なTerm Frequency（TF）は「その文書で何回出たか」です。ただしtheのように全文章へ頻出する語は分類力が低いことがあります。そこでInverse Document Frequency（IDF）で、多くの文書に出るfeatureを弱めます。

代表的には次の形です。

$$ \mathrm{tfidf}(t,d)=\mathrm{tf}(t,d)\times \log\frac{N}{\mathrm{df}(t)} $$

ここでdf(t)はfeature tを含む文書数、Nは全文書数です。実装ではzero division回避のsmoothingやnormalizationが入ります。

scikit-learnのTfidfVectorizerはraw textを直接TF-IDF matrixへ変換し、word / char / char_wb、ngram_range、min_df、max_df、sublinear_tfなどを指定できます（scikit-learn TfidfVectorizer）。

なぜ線形モデルでも強いのか

N-gramではfeature数が数万〜数十万列になり得ますが、1文書が実際に持つfeatureはその一部だけなのでmatrixは疎です。各featureに「この語があるとclass Aへ寄る」という重みを学習する線形モデルと相性がよく、LinearSVCはsparse inputを扱えます（scikit-learn SVM guide）。

Word N-gram と Character N-gram

表現拾いやすいsignal弱点
Word N-gram語彙、phrase、否定を含む短い文脈未知語・typo・形態変化に弱い
Character N-gram語形、suffix/prefix、typo、表記揺れfeature数が増えやすい
char_wb単語境界内の文字pattern単語を跨ぐpatternは拾わない
Word + Character意味のある語と形態patternの補完memoryとtraining costが増える

char_wbは単語境界の内側だけでcharacter N-gramを作ります。scikit-learn公式では、語の端をspaceでpaddingしつつ、単語を跨がないcharacter N-gramとして定義されています（Feature extraction guide）。

2026年SPR Mammography 3位解法は、full reportとfindings sectionに対しword 1–3 gram + char_wb 3–5 / 3–6 gramを別headで作っています（3rd place solution）。4位解法もword 1–3 gramとcharacter 3–5 gramを組み合わせました（4th place solution）。

方法向いている条件主な注意
TF-IDF + Linear modellexical signalが強い、small/medium data、CPU制約長距離contextや意味理解は弱い

重要なのは「Transformerが新しいから常に上」ではありません。targetを決めるsignalが語彙・文字pattern中心なら、疎特徴量のbiasが問題に合うことがあります。一方、同じ語でもcontextによってlabelが変わる問題ではTransformer側が有利になりやすいです。

Kaggleでの実例

SPR 2026 Mammography — 同じCompetitionでBERTとTF-IDFが上位

SPR 2026 Mammography Report Classificationは、ポルトガル語のmammography reportから7クラスのBI-RADSを予測し、metricはmacro F1でした（Competition overview）。

1位解法はPortuguese BERTをStratified 5-Foldでfine-tuneし、max length 512、Focal Loss、fold majority voteを採用しました。作者はTF-IDFを「うまくいかなかった試行」として挙げています（1st place solution）。同じdatasetでもrecipe次第でTF-IDFが最適とは限らないEvidenceになります。

一方3位解法は、複数TF-IDF head + calibrated LinearSVC + LightGBMを構成し、per-class threshold tuningでOOF macro-F1を+0.01867改善し、Private 0.85431を報告しています。作者は複数のTransformer ensembleを試したもののPrivateが0.73–0.80で、lexical / template signalが強いこのdatasetではTF-IDFが安定したと説明しています（3rd place solution）。threshold改善はTF-IDF単独ablationではないため、その点は分離して解釈します。

4位解法も、word N-gramとcharacter N-gramを積んだMulti-Head TF-IDF + SVMを中心にしています。数字をNUMへmaskし、raw report hashをgroup identifierとして近重複のfold leakageを避ける設計でした（4th place solution）。複数独立解法で同系統が成立しているため、定型的な専門文書ではword + char TF-IDFが強いことがあるEvidence Cです。

LLM Detect AI Generated Text 3位 — TF-IDFをTransformerの補完へ

2024年LLM Detect AI Generated Text 3位は、TF-IDF pipelineと12個のDeBERTa-v3-largeをweighted ensembleしました。TF-IDF pipelineへ高confidence pseudo label等を追加した調整で、作者報告ではPrivate scoreが0.893 → 0.927へ上がり、最終選択した2本のTF-IDF pipelineはPrivate 0.970 / 0.974でした（3rd place solution）。

この例では最終的にTransformerとTF-IDFを混ぜています。semantic modelとtoken pattern modelで誤差が異なると、TF-IDFは単体baselineだけでなくensemble diversity sourceになります。

Kaggle LLM Science Exam 19位 — retrieval rerankingにも使える

19位解法はWikipedia candidate retrieval後にTF-IDFでrerankし、prompt / answerとWikipedia sentenceの語彙一致を利用しました。作者はこの2段目を最終scoreに重要だったと説明しています（19th-place solution）。

つまりTF-IDFはclassification専用ではなく、lexical retrieval / rerankingでも候補になります。

注意点

1. Validation/Testの語彙をvectorizerへ混ぜる

fit時にValidationやTest textまで使えば、そのdatasetにどのN-gramが存在するかという情報を見ます。target leakageではなくてもtransductiveになります。productionを模したCVなら、各foldのTrainだけでvocabularyとIDFをfitし、Validationへtransformします。

LLM Detect AI Generated Textではtest vocabulary利用を巡るDiscussionもあり、Kaggle固有のtransductive設定と一般的なdeploymentを分けて考える必要があります（Kaggle Discussion）。

2. N-gram範囲を広げすぎる

word (1,5)やcharacterの広すぎる範囲はfeature数とmemoryを急増させます。まずmin_dfで極端なrare featureを落とし、wordとcharを別々にablationします。

3. Preprocessingでsignalを消す

stop word、記号、数字、改行は「noise」とは限りません。医療reportでは数値表現や定型format、toxicityでは記号や綴りがsignalになることがあります。削除前後をOOFで比較します。

4. Duplicate leakage

TF-IDFは表面的な一致に非常に敏感です。近重複textがTrain / Validationへ跨ぐと、CVを大きく過大評価します。SPR 2026 4位はraw report hashをgroup identifierとして利用しており、3位もnear-duplicateが同foldへ入ることを重要視しています（3rd place solution）。

5. 文脈が必要なtaskへ固執する

TF-IDFは「not good」と「good」の違いをbigramで部分的に拾えても、長い依存関係・照応・論理関係の理解は苦手です。BERT / DeBERTaとのOOF比較で差が明確なら、sparse modelはbaselineやblend候補へ役割を下げます。
